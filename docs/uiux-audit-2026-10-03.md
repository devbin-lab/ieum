## 레퍼런스 비교

사용자가 제공한 Codex 스크린샷과 기존 UIUX 명세를 전체 프레임의 기준으로 삼았습니다. 아이콘 레일, 계정 팝오버, 설정의 좌측 분류와 우측 본문을 따르되, Codex에 있는 다른 기능을 빈 메뉴로 복제하지 않았습니다.

| 기준 | 확인한 패턴 | 이음 적용 |
|---|---|---|
| 사용자 제공 Codex 화면 | 적은 전역 탐색, 문맥별 설정, 계정 메뉴 | 중복 홈 목적지 제거, 설정 제목·적용 범위 고정 헤더, 개인 설정 검색 제거 |
| [Discord Members Page](https://support.discord.com/hc/en-us/articles/15946797617431-Members-Page) | 참여자 목록·역할·검색·필터, 행의 추가 작업과 상세 | 표 정렬, 선택 상세, 참여자별 역할·상태 작업 유지 |
| [Discord Roles and Permissions](https://support.discord.com/hc/en-us/articles/214836687-Discord-Roles-and-Permissions) | 역할 선택 후 권한 편집 | 넓은 창의 목록·상세, 좁은 창의 역할 선택기·상세, 권한 그룹 검색 |
| [Linear Members and Roles](https://linear.app/docs/members-roles) | 관리 설정 안의 참여자 목록, 역할·상태 필터, 행의 더 보기 | 참여자 초대의 우선순위 강화, 보조 관리 작업 분리 |
| [Slack Deactivate a Member](https://slack.com/help/articles/204475027-Deactivate-a-members-account) | 상태 변경은 권한을 가진 관리자에게 한정 | 활성화·비활성화 권한과 기존 확인 절차 유지 |

공식 문서는 정보 구조와 행동 경로의 근거입니다. 해당 제품을 이번에 직접 조작하거나 픽셀 단위로 측정했다는 의미는 아닙니다.

## 발견한 문제와 반영 내용

| 화면 / 문제 | 수정 결과 |
|---|---|
| 홈과 일정 아이콘이 같은 화면으로 이동하고 동시에 선택됨 | 현재 프로젝트 홈 하나로 통합. 알림·계정 레일 유지 |
| 작업 화면에서 현재 프로젝트를 알기 어려움 | 장식용 영어 문구 대신 현재 프로젝트 이름 표시 |
| 작업 표가 카드의 오른쪽을 채우지 못함 | 표의 최소 너비를 실제 가용 너비에 맞춤. 헤더·행 구분선 정렬 |
| 작은 창에서도 8열 표를 가로로 탐색해야 함 | 700px 미만 본문은 제목·상태·현재 처리자·마감일·우선순위가 있는 세로 목록. 나머지는 상세에서 확인 |
| 작은 창에서 요약 카드가 작업 목록을 과도하게 밀어냄 | 최소 높이를 줄이되 글꼴 높이에 따라 늘어나도록 변경. 실제 한글 렌더링에서 발견한 2px 넘침도 수정 |
| 설정 상단의 범위 바와 본문 제목이 공간을 중복 점유 | 제목과 적용 범위를 하나의 고정 헤더로 통합. 콘텐츠 시작 간격 일관화 |
| 개인 설정에 항목이 하나인데 검색·그룹 제목이 있음 | 불필요한 검색과 그룹 제목 제거. 프로젝트 설정에는 검색 유지 |
| 이름 변경·업데이트 버튼이 정보 카드 밖에 분리됨 | 해당 정보 행에 버튼 배치 |
| 참여자 관리의 초대·새로고침·역할 추가·관리자 이전이 같은 강도로 나열됨 | 초대는 주 버튼, 새로고침은 툴팁 아이콘, 역할 추가·관리자 이전은 더 보기 메뉴. 권한 조건 유지 |
| 참여자 행이 각각 둥근 카드여서 열과 선택 관계가 약함 | 공통 열 간격·행 구분선·선택 배경. 상세의 업무 상태 수치를 작은 묶음으로 정리 |
| 새로고침 시각에 초 이하 자리까지 노출됨 | 읽기 쉬운 시:분 표시 |
| 적용하지 않은 필터도 초기화 가능해 보임 | 필터가 없으면 초기화 비활성화 |
| 좁은 역할 화면에서 목록 전체가 권한 상세 위를 차지함 | 작은 창은 역할 선택기로 전환. 선택 즉시 같은 위치에서 상세 확인 |
| 권한 검색 후 첫 결과 위에 불필요한 구분선 | 실제 표시되는 첫 항목을 기준으로 구분선 계산 |
| 동기화 연결 상태를 누를 수 없는 큰 버튼으로 표시 | 연결 정보는 상태 영역에 표시. 사용 가능한 재시도·자동 동기화 동작만 버튼으로 유지 |
| 변경내역 상단에 SQLite→JSON→브랜치 등의 내부 구현 설명 | 변경 건수와 사용자 행동 중심 설명으로 교체. 수동 가져오기·내보내기는 접이식 보조 영역 |
| 알림 설정의 미구현 Discord 연결 표시, 파트 배정의 ‘후속 파트 (설계)’ 열 | 현재 사용할 수 있는 정보만 표시. 저장 데이터와 향후 확장 가능성은 유지 |
| 빈 알림함이 고정 높이 440px로 불필요하게 큼 | 빈 상태는 짧게, 알림이 있을 때는 창 높이에 맞춰 스크롤 |
| 작업 등록창의 별도 스타일과 본문에 포함된 저장 버튼 | 공통 팝업 스타일, 고정 헤더·저장/취소 영역, 본문만 스크롤 |
| 검토자가 보는 안내가 ‘결과를 기다리라’는 의미로 표시됨 | 검토 가능 사용자에게 완료 승인·재작업 요청 안내 표시. 실제 권한 검사 유지 |
| 작은 보조 글자·버튼이 지나치게 흐림 | 공통 보조색, 활성 버튼 글자, 상태·우선순위 색 대비 개선. 버튼의 한글 글꼴 명시 |

로그인·생성·참여, 칸반의 단계와 드래그, 역할 삭제 시 재배정, 관리자 이전 확인은 기존 흐름을 유지했습니다. 완료 잠금, 검토 본문 잠금, 역할·상태 권한, PR/동기화 처리 로직은 변경하지 않았습니다.
