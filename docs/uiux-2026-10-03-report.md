# IEUM UI/UX 명세 반영 결과 — 로컬 검증본

1. 구현한 화면과 흐름

계정 메뉴의 **개인 설정**과 프로젝트 선택 메뉴의 **프로젝트 설정**을 분리했습니다. 프로젝트 이름·적용 범위는 프로젝트 설정의 고정 헤더에 표시합니다. 개인 화면에는 이름·GitHub 식별자·앱 업데이트를, 프로젝트 화면에는 정보·참여자·역할·파트별 배정·알림·동기화·이력을 둡니다. 추가 사이드바 설정 아이콘은 만들지 않았습니다.

참여자는 이름·GitHub 아이디 검색, 독립적인 역할/상태/파트 필터, 필터 초기화, 결과 수/전체 수, 안정적인 이름순 정렬을 지원합니다. 넓은 목록은 참여자/역할/상태/파트 열로 정렬하고 좁으면 정보 행으로 바뀝니다. 행의 추가 메뉴는 허용된 작업만 제공합니다. 본인/소유자를 텍스트로 표시합니다. 상세는 넓은 창의 우측 패널과 좁은 창의 대화상자로 나뉘며 실제 업무 상태별 건수와 관련 업무 필터로 연결됩니다. 필터에서 제외되면 상세를 닫고 이유를 표시합니다.

역할은 단일 선택이며 기존→새 역할·상태·권한 영향을 확인한 뒤 저장합니다. 중복 확인/저장, 원격 대상 변경, 프로젝트 변경, 권한 취소를 검사합니다. 저장 실패 시 창과 초안을 유지하고 최신 저장값 확인/재시도를 제공합니다. 비활성화 전에 남은 업무·검토·통합 대기 PR을 확인하며 인수인계가 필요하면 차단합니다. 재배정은 기존 업무 편집 화면을 사용합니다. 이전 역할이 없는 구버전 비활성 사용자는 직접 역할을 선택해야 합니다.

권한 이름·설명 검색, 읽기 전용 허용 여부, 적용 범위/제한 설명, 역할 참여자→참여자 상세 연결을 추가했습니다. 기존 사용자 정의 역할 추가/수정/삭제와 사용 중 역할의 원자적 재배정은 유지합니다. 저장/취소/Esc/Windows 종료에서 미저장 초안을 보호하며 저장 실패는 창 종료를 막습니다. 중첩 편집창도 순서대로 확인합니다. 참여 요청 거절은 기존 등록 PR을 검증하고 닫는 방식이며 GitHub 협업자 초대와 구분합니다.

프로젝트 전체 집계 라벨을 추가했습니다. 수동 JSON 가져오기는 출처 확인과 작업 변경 권한을 요구하고 기존 프로젝트/형식/충돌 검증을 거칩니다. 자동 GitHub 가져오기는 읽기 전용 사용자도 계속 받을 수 있습니다. 업무 생성 진입점은 이미 동일한 프로젝트 store.canCreate 판정을 사용하고 있어 보존했습니다.

3. 유지한 규칙과 확인한 정책

개설자는 내부 owner이자 관리자이며 ownerId/founderId는 유지합니다. 보호 역할의 일반 재배정·비활성화, 자기 승격, 보유 권한 밖 부여를 금지합니다. manager는 기존 운영자 권한을 유지하며 실제 배정되지 않은 기본 직무 역할을 자동 생성하지 않습니다. worker/viewer/pending/disabled 및 사용자 정의 역할의 기존 활성/권한 판정을 재사용합니다. 구버전 disabled의 이전 역할은 추정하지 않습니다.

review의 현재 처리자는 reviewer, 나머지는 assignee입니다. 내 업무는 현재 처리자=본인이면서 미완료인 업무입니다. 완료는 관리자도 변경할 수 없으며 검토 본문도 잠깁니다. 재작업은 공백 아닌 사유가 필요합니다. 파트와 권한 역할은 별개입니다. 소유권 이전은 이음 관리자만 변경하며 GitHub 저장소 소유권이나 협업자 권한을 바꾸지 않습니다.

SQLite 구조·프로젝트 ID 경계·업무별 JSON/PR·충돌 복구·10초 가져오기·기존 로그인과 자동 업데이트 경로를 유지했습니다. 신규 패키지, DB 마이그레이션, 외부 계정 연결을 추가하지 않았습니다. 수동 가져오기는 actor.canMutate와 trusted 확인을 저장 계층에서 검사하고 자동 가져오기는 기존 흐름을 유지합니다. 관리 변경의 원격 반영과 로컬 업무 변경의 전송 대기를 같은 성공 상태로 표시하지 않습니다.

6. 남은 항목과 2단계

실제 PC에서 창 종료·배율·스크린 리더·원격 권한 오류·GitHub 통신 지연은 사용자 테스트가 필요합니다. 자동 테스트의 통과를 실제 Windows 조작이나 실서비스 검증으로 주장하지 않습니다. 저장 강제 종료/운영체제 종료까지 초안을 영구 보관하는 새 복구 저장소는 도입하지 않았습니다.

기존 수동 역할 생성 기능은 완성된 저장/검증 경로를 유지했습니다. 역할 복제, 역할별 화면 시뮬레이션, 역할 설명/감사 메타데이터 확장, 복수 역할/명시적 거부 모델, 초대 재전송/철회 시스템은 2단계입니다. 필요하면 현재 단일 역할과 ID를 유지하는 호환성 명세부터 별도로 정해야 합니다. 이번 범위를 완료하는 데 추가 권한 정책 결정은 필요하지 않습니다.

8. 후속 수정: 홈 및 프로젝트 선택
