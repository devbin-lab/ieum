# 작업 목록 밀도와 일정 상세 이동

## 조사

| 공식 자료 | 확인한 흐름 | 적용한 설계 |
| --- | --- | --- |
| [Linear 표시 옵션](https://linear.app/docs/display-options) | 목록·보드 전환, 정렬과 필요한 속성 표시 | 사용자가 마지막으로 선택한 작업 보기 유지, 목록은 핵심 속성 중심으로 구성 |
| [Jira 검색 결과 보기](https://support.atlassian.com/jira-software-cloud/docs/change-the-view-of-search-results/) | 중요한 열만 표시하고 작업을 선택해 상세 미리보기 | 목록은 요약, 우측 패널은 상세. 부가 설명과 처리 기능을 모든 행에 길게 펼치지 않음 |
| [Jira 일정의 작업 관리](https://support.atlassian.com/jira-software-cloud/docs/manage-issues-in-your-calendar/) | 일정에서 작업을 선택해 같은 작업의 세부 내용 확인 | 일정 상세에서 작업 화면으로 이동하되 동일 작업과 상태를 유지 |

픽셀 크기와 문구는 위 제품의 규격을 복제한 값이 아니라 이음의 창 크기·한국어 표시량에 맞춘 결정이다.

## 일정에서 작업으로 이동

- 일정에서 연 작업 상세의 고정 헤더에 `작업으로 이동`을 배치한다. 상태 변경·전달과 구분되는 보조 탐색 버튼이다.
- 일정 상세를 닫은 뒤 작업 탭에서 같은 작업 상세를 연다. 상세 패널을 중첩하지 않는다.
- 마지막 작업 보기인 목록 또는 보드를 유지한다. 일정을 마지막으로 보고 있었더라도 이 동작의 목적지는 작업 탭이다.
- 검색·필터 때문에 대상 작업이 사라지지 않도록 탐색 조건을 해제한다. 보관 작업은 보관함을 사용한다.
- 목록의 대상 작업이 50개 페이지 경계 뒤에 있으면 해당 페이지로 이동하고 행을 보이는 위치로 스크롤한다.
- 이동은 작업 내용·버전·GitHub 전송 기록을 변경하지 않는다.

## 목록 구성

- 기존 70~110px 높이 행을 기본 54px로 줄인다. 큰 글꼴에서는 높이를 늘려 텍스트를 보존한다.
- 작업 ID·제목, 상태, 담당자, 우선순위, 일정 기간과 간결한 도구만 배치한다.
- 시작일과 마감일을 같은 기간 열로 묶는다. 연도와 전체 날짜는 툴팁에서 확인한다.
- 파트와 요청 목적 같은 부가 정보는 상세·툴팁으로 제공한다. 제목·담당자는 한 줄로 표시하고 긴 내용에는 전체 값 툴팁을 제공한다.
- 작업 처리는 더보기 메뉴에 모으고 기존 최종 확인 절차를 유지한다. 상단 고정은 작은 핀 버튼으로 바로 조작한다.
- 행 클릭·Enter/Space는 상세 열기이며, 핀·더보기 조작은 행 클릭과 분리한다.
- 좁은 창에서는 열을 잘라내지 않고 가로 스크롤로 확인한다. 기존 50개 단위 페이지를 유지한다.
- 선택한 행과 hover를 구분하고 기존 라이트·다크·포인트 컬러를 따른다. 타이틀바·아이콘바·메인뷰 라운드는 유지한다.

## 검증 범위

일정에서 목록·보드로 이동, 페이지 경계 이후 작업 찾기, 목록 도구 조작과 최종 확인, 고정 정렬, 큰 글꼴·좁은 창을 확인한다. 테스트 데이터는 메모리 DB에만 생성한다. 실제 사용자 프로젝트에는 샘플 작업을 넣지 않는다.
