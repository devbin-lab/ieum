# 이음 · Flutter 데스크톱 0.2.0

GitHub와 개인 SQLite로 팀 작업을 공유하는 Windows 앱입니다. 개발 브랜치는 `codex/flutter-desktop`, 앱 버전은 `0.2.0+5`입니다. 이전 Electron 구현은 `codex/electron-prototype`에 보존합니다.

## 0.2.0 변경 사항

- 왼쪽 위 프로젝트 선택기에서 여러 프로젝트를 전환하고, 로그아웃 없이 새 프로젝트를 생성·참여합니다.
- 계정별 프로젝트 목록, 마지막 프로젝트, 마지막 화면과 목록·칸반 선택을 기억합니다. 로그인 유지 시 생성·참여 화면을 거치지 않고 작업 공간으로 돌아갑니다.
- 일시적인 통신 장애 때 저장된 계정과 로컬 DB로 시작합니다. 연결 복구 후 계정을 재검증하며 인증 취소·계정 불일치는 재로그인이 필요합니다.
- 저장 직후 자동 전송, 약 5초마다 원격 변경 확인. 변경이 없으면 가벼운 조회만 수행하고 오류·GitHub 요청 제한 때는 재시도 간격을 늘립니다. 모든 공유가 5초 안에 끝나는 것을 보장하지는 않습니다.
- 검토 중 작업 내용 잠금, 재작업 시 담당자 수정 허용, 완료 작업은 관리자도 수정 불가. 관리자는 검토 중 배정과 일정을 조정할 수 있습니다. 조회는 허용합니다.
- 내 작업 배정·검토·재작업 알림함과 읽음 상태. Discord 외부 전송은 아직 연결 전입니다.
- 손상 파일과 작업 충돌을 격리해 정상 작업은 계속 가져옵니다. 개인 변경과 대기열을 복구 기록에 보관한 뒤 최신 통합본을 적용할 수 있습니다.
- PR 페이지 누락, 닫힌 PR, 응답 유실, 일시 중지 중 저장, 같은 DB의 동시 저장 문제를 보완했습니다. 자동·수동 통합 모두 현재 역할·작성자·작업 내용을 검증합니다.
- 업데이트 실행 실패 시 해당 배포본의 반복 적용을 막고 가능한 이전 버전으로 복구합니다. EXE와 ZIP 실행 경로를 지원합니다.

## 팀원 PC에서 실행

`Ieum-Windows-x64.exe` 하나를 복사해 실행합니다. Flutter SDK, Git, Node.js는 필요하지 않습니다. 앱·DLL·Visual C++ 런타임은 `%LOCALAPPDATA%\Ieum\builds\<빌드 시각>`에 풀립니다. ZIP을 사용하면 전체 압축을 풀고 `ieum_flutter.exe`를 실행합니다.

1. **GitHub로 로그인**을 누르고 브라우저에서 앱에 표시된 인증 코드를 입력합니다. 토큰을 직접 발급할 필요는 없습니다. 로그인 유지를 켜면 다음 실행에서 계정과 마지막 프로젝트를 복원합니다.
2. 개설자는 **프로젝트 생성**에서 이름, GitHub 저장소, 닉네임, 개인 DB 폴더를 지정합니다. main 브랜치가 있는 저장소의 관리자여야 합니다. 한 저장소에는 한 프로젝트를 만듭니다.
3. 개설자는 **프로젝트 설정 → 참여자 · 역할과 권한 → GitHub 협업자 초대**에서 팀원을 초대합니다. 팀원이 GitHub에서 초대를 수락해야 합니다.
4. 참여자는 같은 저장소에 **프로젝트 참여**를 신청하고 자신의 DB 폴더를 선택합니다. 닉네임과 GitHub 숫자 계정 ID로 개인 브랜치와 가입 요청 PR을 만듭니다.
5. 개설자가 가입 요청에 역할과 담당 파트를 지정하면 작업할 수 있습니다. 가입 승인 자체는 자동화하지 않습니다.
6. 다른 프로젝트는 왼쪽 위 선택기에서 생성·참여·전환합니다. 프로젝트마다 작업과 전송 대기열을 분리합니다. 로그아웃은 로그인 정보를 지우며 프로젝트 DB를 지우지 않습니다.

같은 GitHub 계정을 두 PC에서 사용하면 같은 참여자로 처리합니다. 서버 없이 동작하므로 쓰기 권한을 받은 팀원의 앱이 실행 중이어야 자동 PR 전송·통합이 진행됩니다. 특정 개설자 PC를 항상 켜둘 필요는 없습니다. 참여자에게 저장소 권한이 없거나 보호 브랜치 조건이 충족되지 않으면 GitHub가 작업을 거부합니다.

## 작업 흐름과 권한

| 역할 | 허용 동작 |
| --- | --- |
| 개설자 | 프로젝트 관리, 초대, 가입 승인, 역할·파트 지정, 작업 등록·배정·통합 |
| PD / PM | 작업 등록·배정·일정·우선순위 변경, 검토 관리, 통합 |
| 작업자 | 배정된 작업 수정·진행·검토 요청, 자신에게 배정된 검토 승인·재작업 요청 |
| 열람자 / 가입 승인 대기 / 참여 중지 | 조회, 작업 제출 차단 |

`할 일 → 진행 중 → 검토 → 완료`를 기본으로 하며 검토자가 재작업을 요청하면 원 담당자에게 돌아갑니다. 검토 중 제출 내용과 완료 작업은 잠깁니다. 완료 후 변경이 필요하면 별도 작업을 등록합니다. 기획·프로그래밍 등 후속 파트의 새 작업 자동 생성은 아직 구현 전입니다.

일정과 작업을 목록·칸반으로 전환합니다. 작업 내용, 담당자, 검토자, 지정일, 마감일, 완료일, 우선순위를 관리합니다. 내 할 일·내 검토 요청, 검색·파트 필터와 드래그 상태 이동을 지원합니다. 검토·재작업 등 업무 판단은 담당자가 하며 GitHub PR 자동 통합과 구분합니다.

이음의 역할은 앱 동작을 제한합니다. GitHub 저장소 쓰기 권한을 가진 사용자가 GitHub나 다른 클라이언트에서 직접 main·프로젝트 설정을 변경하는 것까지 차단하지는 않습니다. 참여 중지로 GitHub 협업자 권한이 자동 회수되지도 않습니다. GitHub 보호 브랜치·필수 검사와 별도 서버 검증은 구성하지 않았습니다.

## 동기화와 복구

- 저장과 전송 대기열 기록은 같은 SQLite 트랜잭션에서 처리합니다. 자동 동기화를 끈 동안에도 작업을 보존하며 다시 켜면 보냅니다.
- 작업별 브랜치는 `ieum/tasks/<GitHub 계정>/<작업 ID>`, 파일은 `.ieum/changes/<GitHub 계정>/<작업 ID>.json`입니다. SQLite 파일과 앱 소스는 전송하지 않습니다.
- 같은 작업의 열린 PR에는 변경을 추가합니다. 다른 작업 또는 이미 통합한 작업의 새 수정은 새 PR을 만듭니다. 닫힌 미통합 PR은 재제출하고, 응답을 못 받았어도 이미 main에 반영되었으면 전송 완료로 복구합니다.
- 앱은 저장 직후 제출하고 약 5초 주기로 변경을 확인합니다. 일반 실패는 간격을 늘려 재시도하며 `Retry-After`와 GitHub 요청 한도를 준수합니다. 프로젝트 설정에서 상태·보류 이유와 수동 재시도를 확인합니다.
- 자동 통합은 기본으로 켜집니다. 작업자는 자신의 PR, 개설자·PD/PM은 팀의 작업 PR을 처리합니다. 작성자의 현재 역할과 배정, JSON 한 파일, 최신 기준본, 상태 전환, main 변경 여부를 검사합니다. 초안·가입 요청·Git 충돌·보호 브랜치 조건 미충족은 자동 통합하지 않습니다.
- 손상 파일은 격리합니다. 어떤 작업인지 판별할 수 없으면 해당 통합의 안전성을 판단할 수 없어 보류할 수 있습니다. 정상 작업 가져오기는 계속합니다.
- 같은 작업의 충돌은 개인 내용과 기준본을 보존합니다. **개인 변경 백업 후 통합본 적용**은 로컬 DB의 `conflict_backups`에 작업·기준본·대기열을 남긴 뒤 원격 내용을 적용합니다. 백업 자동 재전송은 하지 않습니다.
- `.ieum/changes` 하위 트리를 따라 조회하여 기존 1,000개 파일 제한을 제거했습니다. 파일당 디코딩 후 1MiB 제한, 알 수 없는 작업 필드·잘못된 버전·날짜를 거부합니다. 대규모 작업에서 GitHub API와 동기식 DB 처리 비용은 남아 있습니다.
- JSON 내보내기·수동 가져오기도 지원합니다. 수동 파일 가져오기는 전체 검증 후 적용하며, 자동 동기화는 작업 단위로 충돌을 격리합니다. 삭제 병합은 지원하지 않습니다.

## 로그인과 저장 위치

기본 인증은 GitHub OAuth Device Flow입니다. 공개 Client ID는 `Ov23liDTP1YEtuI7SAx0`, Client Secret은 사용·배포하지 않습니다. 저장소 커밋·PR 권한과 만료 토큰 갱신 권한을 요청합니다. OAuth 승인은 협업자 초대를 대신하지 않습니다.

로그인 유지 시 access/refresh token과 계정 정보는 Windows 자격 증명 관리자 `Ieum/GitHub/OAuth/Ov23liDTP1YEtuI7SAx0`에 보관합니다. 토큰은 DB·프로젝트 목록·JSON·배포본에 넣지 않습니다. 로그인 유지 해제와 고급 세션 토큰은 메모리 전용입니다. 재인증 실패 후 다른 Git 계정으로 자동 전환하지 않습니다.

DB는 선택한 폴더의 `ieum-<프로젝트 ID>-gh-<계정 ID>.sqlite`에 저장합니다. `%APPDATA%\Ieum-Flutter-Prototype\project-preferences.json`에는 계정별 프로젝트 목록과 마지막 경로를 기록합니다. 기존 단일 프로젝트 설정은 자동 변환하며 `.bak`로 복구할 수 있습니다. `IEUM_FLUTTER_DATA_DIR`로 설정 위치를 바꿀 수 있습니다. 예시 작업은 자동 테스트에서만 사용하며 기존 예시 DB는 자동으로 열지 않습니다.

## 자동 업데이트와 개발자 빌드

업데이트는 작업 저장소와 별개인 `devbin-lab/ieum`의 GitHub Releases를 사용합니다. 시작 시와 4시간마다 정식 배포본을 확인하고 EXE 크기·SHA-256 digest를 검증합니다. 내려받은 업데이트는 다음 실행 또는 **업데이트 후 재시작**에서 적용합니다. 기존 DB와 로그인 정보를 보존합니다.

런처는 시작 확인과 짧은 안정화 시간을 거칩니다. 실패한 배포본은 격리하고 이전 실행 파일이 있으면 복구합니다. `IEUM_DISABLE_UPDATES=1`은 확인과 자동 적용을 끕니다. 배포 저장소가 비공개이므로 해당 저장소의 읽기 권한이 있어야 업데이트할 수 있습니다. 다운로드 리다이렉트에 GitHub 토큰을 전달하지 않습니다.

개발 환경은 Flutter 3.47.5 / Dart 3.13.4입니다.

```powershell
flutter pub get
flutter analyze
flutter test
.\windows\distribution\test-launcher.ps1
.\build-windows.ps1
.\package-windows.ps1
```

`build-windows.ps1`은 일반 Flutter 빌드 후 필요하면 기존 MSVC·CMake를 사용합니다. 소스만 복제한 PC에는 Flutter SDK와 Windows C++ 빌드 도구가 필요합니다. `pubspec.yaml`과 `lib/app_release.dart`의 버전을 함께 올리고 소스 커밋에 `v<버전>` 태그를 붙입니다. 정식 GitHub Release에 `Ieum-Windows-x64.exe`를 첨부합니다. ZIP은 수동 설치용이며 Draft·Pre-release는 자동 업데이트에서 제외합니다.

## 검증 범위

자동 테스트에서 로그인 저장·복원·오프라인·계정 불일치, 프로젝트 전환·설정 저장 실패 복구, 두 사용자 작업 흐름, 동시 저장, 검토 잠금, 충돌 격리, 페이지네이션, 1,001파일, 응답 유실, 요청 제한과 대기열 복구를 확인합니다. 가짜 GitHub API를 사용하며 사용자 저장소에 테스트 작업을 만들지 않습니다.

Flutter 테스트 엔진에서 1480×940·1160×740 레이아웃, 프로젝트 메뉴, 목록·칸반, 드래그·작업 등록·재작업 흐름을 검사합니다. Windows 런처는 창을 만들지 않는 실행 파일로 업데이트 실패·격리·복구를 검사합니다. 실제 사용자 데스크톱을 제어하는 테스트는 하지 않습니다.

실제 두 PC 사이 전체 OAuth·PR·업데이트 흐름과 Discord 외부 전송은 검증 범위에 포함하지 않습니다. 0.2.0은 개선된 테스트 릴리스이며 위 기능 전체의 실서비스 무결성을 보장하는 1.0 선언은 아닙니다.
