# 파트 기반 작업 통제 설계

> 후속 변경: [상태와 담당자 전달 분리](collaborative-handoff-plan.md)가 현재 수신자 기반 편집 통제를 대체한다. 파트는 배정·내 할 일·알림에 사용하며, 미완료 작업은 모든 활성 참여자가 편집한다. 아래 내용은 이전 설계 경과다.

## 조사한 기존 상태

- 파트/역할마다 기능 권한을 합산하는 정책과 수동 작업 이동이 실제 처리 기준이었다.
- 새 자동화 캔버스의 카드, 좌표, 연결, 수신 조건은 위젯 메모리에만 있었다.
- 기존 자동화 데이터는 보관 상태이고 실행 연결은 비어 있었다.
- SQLite 저장과 GitHub 업로드/PR 통합은 공통 작업 변경 검증기를 사용한다.

## 영역별 설계와 연결

| 영역 | 책임 | 저장 및 연결 |
| --- | --- | --- |
| 파트/참여자 | 파트 CRUD, 다중 소속, 승인/비활성, 관리자 이전 | 기존 ID 보존. 파트에는 참여자 관리·역할 관리 두 권한만 설정 |
| 자동화 편집기 | 카드 배치, 경로, 보내는 파트, 받는 파트 또는 개인 | 프로젝트 `workflowSheet` 저장/적용. 카드 ID와 실행 단계 ID 분리 |
| 작업 처리 대상 | 현재 전체/파트/개인 대상, 마지막 경로 | 작업 JSON의 `workflowTarget`, `workflowPerson`, `workflowRoute` |
| 공통 정책 | 내용 수정, 직접 전달, 승인/반려, 관리자 회수 | 로컬 저장·업로드·PR 통합에서 동일 검증 |

### 운영 규칙

1. 파트의 관리 권한은 참여자 관리와 역할 관리 두 가지다. 참여자 관리에는 일반 참여자의 승인·파트 배정·활성 상태 변경이 포함되고, 역할 관리는 파트·권한 구성의 추가·수정·삭제를 허용한다.
2. 작업 등록·정보 수정·진행·검토·통합은 활성 참여자에게 기본 허용한다. 별도 기능 권한 체크박스는 없으며 실제 수정·전달은 현재 수신 대상과 경로 조건을 판단한다.
3. 일반 작업 단계는 현재 대상이 내용을 수정한다. 검토 단계에서는 제출 내용이 잠긴다.
4. 검토는 승인 또는 코멘트를 포함한 반려 경로로 처리한다. 완료는 수정과 일반 이동이 잠긴다.
5. 수신 대상은 선택한 경로에서 작업으로 복사한다. 다음 단계의 출발 조건으로 역산하지 않는다.
6. 같은 목적 단계에 여러 수신 경로가 있으면 정확한 경로를 선택하고 최종 확인한다.
7. 관리자는 잠긴/잘못 전달된 작업을 일반 단계와 활성 작업자에게 회수한다. 내용과 코멘트를 보존한다.
8. 파트는 안정된 ID로 연결한다. 이름 변경으로 경로의 의미가 바뀌지 않는다.
9. 소유자 본인도 파트를 추가·해제할 수 있다. 일반 참여자 관리 권한으로 소유자의 관리자 신분·활성 상태를 변경할 수 없다.
10. 관리자 이전·작업 회수·단계 및 자동화 설정은 프로젝트 소유자가 관리한다. 관리 권한을 위임받았어도 자신이 보유하지 않은 관리 권한을 새로 부여할 수 없다.

### 실제 처리 흐름

- 기본 연결은 `확인중 → 진행중 → 검토 → 완료`, 검토 반려는 확인중이다. 일반 단계는 활성 참여자 전체가 수정하고, 검토에서는 전체가 승인·반려할 수 있지만 제출 내용은 잠긴다.
- 특정 파트·개인이 지정된 첫 경로에서는 최초 작업 담당자가 확인한다. 전달하려면 현재 수신 대상이면서 보내는 파트 조건에도 맞아야 한다.
- 예를 들어 기획에서 PD 전체로 검토를 보내면 활성 PD 구성원 모두가 승인·반려할 수 있다. 기획자는 제출 내용을 수정할 수 없다.
- 같은 단계 사이에 파트별 경로를 여러 개 지정할 수 있다. 기존 카드를 다시 연결하면 새 경로를 추가한다. 편집 중 경로를 바꿔도 초안을 유지하고 한 번에 적용한다.
- 현재 전달자의 소속과 일치하는 전용 경로가 있으면 같은 출발 단계·동작의 모든 작업자 경로는 제외한다. 여러 파트에 소속되면 일치하는 전용 경로들을 모두 선택할 수 있다. 일치하는 경로가 없으면 전체 경로가 기본 경로다.
- 전용 경로의 수신자가 비활성/부재인 경우에도 전체 경로로 우회하지 않는다. 검토의 승인과 반려는 각각 독립적으로 우선순위를 판정한다.
- 반려는 코멘트와 함께 설정된 단계·파트·개인으로 돌아간다. 기존 작업 담당자 정보와 현재 처리 대상은 따로 보존한다.
- 소유자에게 관리자 이전·자동화 설정과 작업 회수 예외를 둔다. 관리 권한 때문에 다른 개인의 알림을 자동으로 구독하지 않는다.
- 작업 메타데이터의 담당자와 실제 현재 수신 대상은 구분한다. 메타데이터 수정으로 자동화의 처리 대상을 우회해서 바꿀 수 없다.
- 활성 참여자는 다른 참여자가 작성한 유효한 작업 PR도 통합할 수 있다. 통합 시 작성자와 작업 변경의 자동화 규칙, 최신 main/PR 및 계정 상태를 검증한다.
- 카드·연결을 편집하는 동안은 초안이다. `저장 · 적용` 이후 실제 작업의 이동 버튼과 검증에 반영한다.
- 전달 조건 라벨은 드래그해 배치하며 클릭하면 조건을 편집한다. 위치는 경로별 배치 오프셋으로 저장한다. 확대·이동과 연결선 표시가 이를 반영하고, 라벨 위치 변경은 전달 정책과 최종 확인을 무효화하지 않는다.
- 자동 정렬은 등록된 단계 순서대로 카드를 가로 배치하고 같은 단계의 복제 카드는 세로 배치한다. 라벨 오프셋도 초기화하며 저장 전 초안에만 반영한다. 전체 보기는 카드와 라벨을 함께 포함한다. 역방향 연결은 카드 위로 돌아가도록 표시한다.

### 구현 상태

파트/참여자 관리, 시트 저장, 작업 처리 대상, 로컬 저장과 업로드·통합의 정책 연결을 완료했다.
예전 작업 기능 권한 데이터와 보관된 자동화는 읽을 수 있지만 새 운영 권한으로 적용하지 않는다. 새 파트에서 선택한 두 관리 권한은 참여자 소속에 따라 적용한다.
실제 계정 간 작업 전달과 앱 사용 확인은 아직 수행하지 않았다.

### 저장과 동시 변경

- 시트 저장은 최신 프로젝트와 관리자 상태를 다시 확인하고 최초 그래프와 비교한다.
- 최종 전달 확인은 작업 버전, 현재 참여자/소속, 실행 경로를 다시 확인한다.
- 카드 좌표만 바뀌면 실행 규칙이 같으므로 준비된 전달을 무효화하지 않는다.
- 삭제된 파트·단계·비활성 수신자를 전체 작업자로 자동 치환하지 않는다.
- 업로드와 통합은 최신 승인 작업과 정책에 대해 수신 대상 조작 및 단계 건너뛰기를 검증한다.

### 이전 데이터

- 이전 작업에 처리 대상이 없으면 기존 담당자/검토자를 개인 대상으로 해석한다.
- 이전 파트/사용자 역할의 이름과 ID, 참여자 소속·활성 상태를 보존한다.
- 이전 작업 기능 권한은 새 운영 정책에 적용하지 않는다. 관리 권한 배정이 관리자 소유권으로 승격되지는 않는다.
- 저장되지 않았던 구 캔버스 배치는 복구할 원격 데이터가 없다. 처음에는 기본 단계 연결을 사용한다.
- 이전에 보관한 자동화 데이터는 자동으로 되살리지 않는다.
- 읽기 정규화는 원격 저장소에 쓰지 않는다. 다음 승인된 설정 저장이 새 형태를 보존한다.

## 검증 범위

코드 분석, 정책 단위 테스트, 저장/동시성/API 테스트와 위젯 코드 테스트만 수행한다.
실제 앱 사용, 실제 계정 간 전달 및 네트워크 환경의 작동 확인은 사용자가 수행한다.
GitHub 저장소 자체의 직접 쓰기 권한은 앱 내부 작업 규칙과 별개다.
