# 새 작업 저장 종료 및 구버전 복귀 수정

2026-10-08 사용자 보고: 새 작업 저장 직후 앱이 다시 시작되었고, 최근 프로젝트를 열 때 지원하지 않는 작업 항목 오류로 막혔다.

## 확인한 원인

Windows 이벤트 1000에서 빌드 `20261008-073919`의 `0xc0000005` 접근 위반을 확인했다. 실행기는 앱 사용 중 발생한 종료도 시작 실패와 같은 경로로 처리하여 `20261008-033356`을 실행했다. 이전 코드의 엄격한 JSON 검사는 새 `deletedAt` 항목을 읽지 못한다. 사용자 SQLite를 읽기 전용으로 확인한 결과 무결성이 정상이고 삭제 기록 두 개가 보존되어 있었다. 새 작업 저장 기록은 없었다.

프로젝트 DB를 SQLite backup API로 임시 사본에 복제했다. 일반 Flutter 검사에서는 재열기·저장이 통과했지만 같은 코드의 Windows Release/AOT 실행은 저장 중 같은 접근 위반으로 종료했다. 단계 추적으로 `_save`의 담당자 검사 구간까지 좁혔다. 레코드 반복과 nullable 등록·수정 분기가 섞여 있던 검사를 명시적으로 타입이 지정된 작은 메서드로 분리하고 인라인하지 않도록 유지했다. 이후 같은 실제 DB 사본으로 저장이 완료되고 종료 코드 0을 확인했다. 권한·비활성 담당자 검사와 기존 담당자 유지 규칙은 보존했다.

## 수정

- `TaskStore._validateAssignedMember`: 등록·수정의 담당자 검사 분리. 작업 저장과 최신 버전 검사는 유지한다.
- 실행기: 시작 완료 후 런타임 오류는 이전 빌드를 자동 실행하지 않는다. 최신 빌드 포인터를 유지하고 종료 코드를 한 파일에 기록한다. 초기 시작 실패와 정상 닫기는 별도 처리한다.
- 지원하지 않는 작업 형식 메시지: 데이터가 보존되며 최신 실행 파일로 열어야 한다고 안내한다. 알 수 없는 항목을 삭제하거나 무조건 허용하지 않는다.

## Release 회귀 진입점

코드 검사만으로 Release 오류를 재현해야 하므로 Windows runner의 임시 `FLUTTER_TARGET`을 `test/support/task_registration_release_probe.dart`로 지정해 빌드한다. 프로세스 결과는 `IEUM_REGISTRATION_PROBE_RESULT`로 지정한 파일에 기록되고 네트워크·사용자 DB에 접근하지 않는다. 실행 후 생성 설정의 목표를 반드시 `lib/main.dart`로 되돌리고 제품 앱을 다시 빌드한 다음 패키징한다. 검사 진입점을 제품 실행 파일로 배포하지 않는다.
